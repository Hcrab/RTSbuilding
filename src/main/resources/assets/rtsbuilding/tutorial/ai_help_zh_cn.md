# RTSBuilding 1.20.1 Forge 操作教程

## 开始使用

按 `G` 打开 RTSBuilding，进入俯视建造视角。再次按 `G` 或 `Esc` 退出。

界面分为三块：

- 顶部栏：切换交互、储存绑定、漏斗和旋转模式，打开快速建造、范围隐藏、设置与求助入口。
- 底部栏：查看储存物品、选择方块和工具、使用蓝图、远程合成和管理插件。
- 侧边悬浮窗：打开箱子或机器界面时出现，用于在容器、背包和 RTS 储存之间搬运物品。

进入 RTS 后，使用 `W` / `A` / `S` / `D` 平移镜头，`Space` 上升，左 `Shift` 下降；按住疾跑键可以加速。按住右键拖动旋转视角，按住中键拖动平移镜头，滚轮缩放。短按中键会选取准星指向的方块。

按住 `Alt` 会在鼠标附近打开模式轮盘。把鼠标移向交互、储存绑定、漏斗或旋转，再左键确认。

也可以按 `I` 切到交互、`L` 切到储存绑定、`R` 切到旋转。`F` 用作快速漏斗：按住时吸取，松开后回到原模式。

`Ctrl + 右键` 让玩家走向目标位置，快速连按两次会尝试精确移动到目标方块上方。按 `Q` 会把当前选中的一个物品丢到鼠标指向的位置。顶部提示会显示当前模式和下一步操作。

## 第一次远程建造

1. 点击顶部栏“储存绑定”。
2. 对准箱子，左键绑定为可存可取；右键绑定为仅提取。
3. 在底部栏“储存空间”找到方块，点击将它设为当前放置物品。
4. 切回“交互”模式，对准目标方块面右键放置。
5. 在箱子、机器等可互动方块上放置时，按住 `Shift` 再右键。

点击底部快捷栏的空手按钮可取消物品选择。刚建好的整组方块可用 `Ctrl + Z` 撤销。

## 顶部栏模式

### 交互

交互是默认模式。右键优先使用方块、机器、箱子、门和实体；没有可用互动时，会尝试放置当前选中的物品。左键使用当前选中的工具远程挖掘。`Shift + 右键` 优先走自然放置链路。

### 储存绑定

左键绑定可存可取的储存，右键绑定仅提取储存。鼠标停在储存绑定按钮上，可打开绑定详情、刷新状态或修改绑定方式。

### 漏斗

先绑定可存入的储存。切到漏斗模式，把鼠标移到掉落物附近，按住 `F` 或右键吸取，松开停止。

### 旋转

选择旋转模式，左键点击已放置方块，再左键点击方块周围出现的旋转圆弧。左右圆弧控制水平旋转，上下圆弧控制垂直翻转；方向键或小键盘 `2` / `4` / `6` / `8` 也可以选择方向。右键仍然用于拖动镜头。

要预选下一次放置的方块状态，先选中方块并把鼠标放在目标位置，然后按 `R`。左键选择状态，右键或 `Esc` 取消；有多页候选时使用左右翻页按钮或方向键。

### 快速建造与范围破坏

点击快速建造按钮，选择“范围建造”或“范围破坏”、形状和填充方式。范围建造用右键完成各个点位，范围破坏用左键完成各个点位；预览锁定后按确认键提交，默认确认键为 `Enter`。

直线、方形、圆和球体使用 A/B 点；直线和圆支持水平或垂直方向。墙、圆柱和立方体还需要确定高度。“高级”可为墙、圆柱、球体和立方体提供三维框与方向箭头。“连接”会为斜向直线或墙补齐拐角，使路径保持面相邻。

“连锁”位于范围破坏中。左键目标方块后，它会寻找相连的同类方块；面板中的上限控制最多处理数量。开启生存平衡时，连锁由“连锁破坏插件”独立解锁。泥土、雪、沙子等软方块不需要采掘等级插件；石头及以上方块仍需对应等级插件和可用的真实工具。范围建造和范围破坏的线框、方块虚影与动画可在设置中分别开关。

创造模式的范围建造会额外显示“覆盖”。打开后，提交的形状会直接替换目标位置上的现有方块，并忽略实体占位；生存模式不会显示也不能请求这项能力。

### 范围隐藏

范围隐藏只在客户端隐藏已有方块，并让 RTS 射线穿过隐藏区域，不会破坏真实方块。

打开范围隐藏后，左键设置两个角点，滚轮调整高度，按 `Enter` 创建。左键已有隐藏盒可选择它；点击六个方向箭头后用滚轮调整对应边界。选中后按 `Delete` / `Backspace`，或点击窗口里的删除按钮移除。

范围隐藏按存档分别保存，不会带到另一个世界。

### FTB 任务检测

同时安装 FTB Quests 和 FTB Teams 后，顶部栏会显示任务检测按钮。点击后会扫描玩家背包和已绑定储存，为不消耗物品、也不要求合成提交的物品任务更新进度。需要交付物品或要求亲手合成的任务仍按任务自己的方式完成。

## 储存空间和快捷栏

底部栏“储存空间”显示玩家快捷栏、RTS 快捷槽、绑定的箱子、机器、储存系统和可用流体。

创造模式玩家会看到额外的“创造”标签页，可按原版和模组创造标签分类、搜索并选择物品。它只提供创造放置选择，不会修改玩家背包。

- 搜索框按物品名、材料名或模组名过滤。
- 分类栏缩小物品范围。
- 排序按钮可按数量、模组或名称排列，并切换升降序。
- 点击物品可选择为当前放置物品。
- 玩家快捷栏 1–9 可直接选择真实工具或物品。
- 选中储存物品后，将鼠标停在空白 RTS 快捷槽并按 `P` 绑定；`Shift + 点击` 已绑定槽位可清空。
- 右键桶或储液物品会尝试向当前绑定的流体储存转入一桶流体。

开启“自动存入”后，RTS 挖掘产物优先进入绑定储存；关闭后掉落在原地。开启“Shift 存入”后，在背包、箱子或机器界面对物品 `Shift + 右键`，可直接送入 RTS 储存。

## 合成面板

安装合成终端插件后，点击底部栏 `C` 或按键盘 `C` 打开合成面板。搜索目标物品，右键物品图标打开数量窗口，输入数量后确认。材料从当前可用储存中消耗；缺少材料时面板会显示缺口。

安装 JEI 后，可先查看配方，再回到 RTSBuilding 搜索并制作。

## 蓝图空间

点击底部栏“蓝图空间”。支持导入 `.nbt`、`.schem`、`.schematic`、`.litematic` 和 Building Gadgets `.json`。

选中蓝图后，世界中会出现预览。右键目标方块固定预览；使用方向按钮、方向键和 `Page Up` / `Page Down` 微调位置，按 `R` 顺时针旋转、`Shift + R` 反向旋转。按 `X` 取消当前蓝图和预览。检查位置和材料后点击放置。

创建蓝图时：

1. 点击“创造新蓝图”。
2. 在世界中左键选择第一个角和对角；只保存一个方块时，选完第一个角直接按 `Enter`。
3. 点击范围内的方块可排除或重新加入；点击六个方向控制柄后用滚轮调整边界。
4. 用方向键和 `Page Up` / `Page Down` 移动整个选择框。
5. 按 `Enter`，输入名称并保存。

生存模式会检查材料；创造模式不消耗材料。蓝图包含缺失方块时，面板会标出缺失内容。

## 侧边悬浮窗

打开背包、箱子、工作台或机器界面时，侧边悬浮窗可显示当前 RTS 储存和 Craft 入口。按住拖拽按钮可移动，位置自动保存。

点击储存舱物品可拿取；鼠标拿着物品时，点击导入区域或储存格可送回储存。左键送回一组，右键送回一个。悬浮窗可在 RTS 设置中关闭。

## 生存平衡和插件

生存平衡由单人存档、整合包或服务器配置决定。多人游戏以服务器配置为准。

打开背包，点击屏幕顶部的 `RTS` 按钮，或在 RTS 底部栏点击“插件管理”。插件是普通物品，可从配方、任务、商店或战利品获得。

- RTS 相机：RTS 视角、基础交互和 16 格基础操作半径。
- 远程控制核心：远程放置、远程挖掘和旋转。
- 石制采掘插件：挖掘石头级方块。
- 铁级、钻石级和无限制采掘插件：逐级提高 RTS 采掘能力。
- 存储整合插件：储存绑定、浏览、自动存入、漏斗、流体和远程 GUI。
- 合成终端插件：远程合成。
- 连锁破坏插件：解锁连锁。
- 范围破坏插件：解锁形状批量挖掘。
- 蓝图插件：蓝图库、预览和放置。
- 范围隐藏插件：局部视觉隐藏。
- 外场部署插件：绕过家园附近的启动限制，并允许更自由地迁移家园。
- 范围扩展 I / II / III：分别提供 16 / 32 / 48 格操作半径；最大范围扩展使用服务器允许的最大半径。

泥土、雪、沙子等软方块不需要采掘插件。石头、矿石和更高等级方块需要对应等级插件，也仍需真实工具能够挖动目标方块。

## RTS 家园和范围

生存平衡开启后，先在背包顶部进入“RTS 家园”，点击“设置初始家园”，回到 RTS 视角后左键目标方块确认。设置目标必须位于进入选择状态时附近的 3×3 区块内。

没有外场部署插件时，玩家必须站在家园区块或周围八个相邻区块内打开 RTS，即以家园区块为中心的 3×3 区块区域。站在外面会收到醒目的距离提示。

成功打开后，本次可操作范围以打开 RTS 时玩家所在方块为中心，沿 X/Z 正负方向各延伸当前操作半径，因此是正方形，不是圆形。家园只决定能从哪里打开 RTS，不会再与本次操作范围取交集。换位置重新打开，操作中心也会改变。

## 设置与小贴士

点击右上角齿轮打开 RTS 设置：

- RTS UI 缩放：只改变 RTSBuilding 顶部栏、底部栏和悬浮窗。
- 灵敏度与镜头平滑：调整拖拽、平移和滚轮手感。
- 自动存入、Shift 存入与工具保护：调整个人操作习惯。
- 预览和动画：分别控制方块虚影、线框、破坏动画和范围破坏骨架。
- 储存刷新：可控制每 30 秒自动刷新，以及是否让手动刷新按钮变绿。
- 回收 RTS 放置方块：直接拆回 RTS 记录过的放置方块，不检查工具、采掘等级和精准采集。
- Jade 跟随鼠标 / 在 RTS 中隐藏 Jade：避免 Jade 挡住顶部提示。
- 容器悬浮窗：控制背包、箱子和机器旁的 RTS 面板。
- 伤害提示与低血量退出：避免俯视时忽略玩家本体受击。

原版背包顶部的 RTS 按钮会自动居中，不跟随其他界面偏移。与其他模组按钮冲突时，可在 RTSBuilding 模组配置中关闭它。

范围操作的确认键默认为 `Enter`，可在 Minecraft 按键设置中搜索 RTSBuilding 修改。

整合包和服务器规则不在齿轮面板中调整。请在“模组 / Mods → RTSBuilding → 配置 / Config”中修改，或编辑服务器的 `config/rts_building/rtsbuilding-common.toml`。

## 常见问题

### 为什么按钮不见了？

生存平衡开启后，按钮随已安装插件解锁。打开插件管理，安装对应插件并刷新。

### 为什么无法挖掘？

切回交互模式，确认已安装远程控制核心。挖石头、矿石或更高等级方块时，再确认采掘插件等级和当前选中的真实工具。屏幕下方的提示会说明因采掘等级跳过的方块。

### 为什么漏斗没有持续吸取？

先绑定可存入的储存，切换到漏斗模式，然后把鼠标放在掉落物附近并按住 `F` 或右键。

### Jade 挡住顶部提示怎么办？

打开 RTS 设置，让 Jade 跟随鼠标，或在 RTS 界面中隐藏 Jade。

# 技术信息附录

这份附录面向维护者、整合包作者和协助排障的 AI。玩家第一次游玩时不需要阅读它；实际操作步骤仍以各篇玩家教程为准。

附录描述的是相对稳定的责任链、检查顺序和设置语义，不绑定具体代码行号。每次发布新版本前，应对照生产代码检查本页。

## 一次 RTS 操作怎样走完整条链路

### 1. 客户端输入与输入所有权

RTS 界面打开后，鼠标和键盘输入先经过界面输入路由。路由按可见层级决定谁拥有这次输入：

1. 模态弹窗、文本框和浮动窗口优先。
2. 顶部栏、底部栏及其子面板其次。
3. 形状选择、蓝图捕获、范围隐藏等正在进行的工具状态再次。
4. 没有 UI 或工具消费输入时，才交给世界交互和相机。

因此，“点了没有反应”不一定是服务端拒绝，也可能是弹窗、文本框、滚动区域或仍未完成的 A/B 点选择消费了输入。滚轮同样遵循所有权：鼠标位于可滚动面板上时不应继续缩放相机。

相机输入与世界操作输入是两条职责不同的链路。中键拖屏、右键转换视角、W/A/S/D 与升降键移动、滚轮缩放只改变客户端镜头；普通交互、放置、挖掘和批量操作才会形成服务端请求。退出 RTS、死亡、断线、换维度或关闭世界时，客户端和服务端都应清理相机及会话状态。

### 2. 模式、工具状态与射线

顶部栏模式决定同一按键代表什么动作。交互、移动、漏斗、快速建造、范围隐藏等模式各自只解释属于自己的输入。

需要世界目标的动作使用 RTS 相机射线，而不是玩家身体朝向。客户端从镜头和鼠标位置计算方块、方块面或实体目标；预览也使用同一目标语义。批量工具可能把第一次命中的位置冻结为 A 点，再等待 B 点、尺寸、旋转或确认键。若预览位置正确而提交位置错误，优先检查“预览射线”和“网络请求中发送的坐标/面”是否一致。

### 3. 客户端请求与网络边界

客户端只负责表达玩家意图，例如：

- 在某个方块面放置所选物品。
- 对某个方块进行远程交互或挖掘。
- 提交连锁目标或范围形状。
- 放置指定蓝图及其旋转、锚点。
- 绑定、提取、插入、合成或刷新储存。

客户端预览不是执行结果，也不拥有最终权限。网络处理器收到请求后必须切回服务端主线程，再解析玩家、会话和目标。任何物品、权限、插件、工具、范围和世界修改判断都以服务端结果为准。

若玩家点击后 `latest.log` 中完全没有相应服务端请求或工作流记录，应优先检查客户端输入所有权、模式状态、射线目标和网络发送；若服务端收到请求后拒绝，再沿服务端检查点排查。

### 4. Pipeline、Workflow 与 Task Engine

三者职责不同：

- **Pipeline** 是一次操作的有序检查与准备链。它验证会话、维度、生存进度、工具、目标和权限，借出真实物品/工具，执行或提交任务，最后返还工具、记录历史并刷新 UI。Pipe 可以成功、失败或有理由地跳过。
- **Workflow** 是玩家可见的长任务身份和生命周期。它持有类型、优先级、进度、暂停/恢复/完成状态，并向客户端工作流面板同步。
- **Task Engine** 是服务器每 tick 的公平执行器。它在全局时间预算和单位预算内轮转不同玩家的建造、挖掘、蓝图和其他后台任务，避免一个大型任务独占主线程。

小操作可能在一次 Pipeline 中完成；大型建造、范围破坏和蓝图通常由 Pipeline 校验后进入 Workflow/Task Engine，分多个 tick 执行。预览已出现只说明客户端选择成功，不代表服务端校验或任务入队已经成功。

持久化 Task 是长任务的权威状态，Workflow 只是面向玩家的投影。暂停游戏、离开世界或重新进入时，墙上时间不能把仍存在的非终态 Task 当成超时垃圾；恢复后应继续从持久化进度执行。最后一条投影消失时，服务端必须发送空闲状态清除客户端旧进度；玩家点击已失效条目的叉号时，也会触发一次权威状态对账。

单个持久任务的 payload 受 40 MiB 和 100 万 NBT 节点双重上限保护。大型范围任务超过上限时，Task Engine 会只终止该任务并保留最后一个合法检查点，不允许容量异常逃出服务器 tick；其他任务和玩家已有的撤回历史不会因此被清空。

新的玩家工作流必须优先于未钉住的旧工作流。达到工作流面板或对应任务族上限时，Task Engine 会在当前维度和相关任务族内淘汰最旧的未钉住任务；只有所有相关旧任务都已钉住时，新请求才会因上限被拒绝。非终态持久任务如果已经失去合法的可见 Workflow 投影，会被终止并清理，不能以“隐藏工作流”继续占用名额；旧任务恢复投影时也不能反向挤掉玩家刚创建的新工作流。内部漏斗和恢复辅助任务仍可隐藏运行，但不占用玩家工作流槽位。

### 5. 结构化诊断日志

破坏类操作使用固定关联链 `trace → seq → op → workflow → task`。客户端按下一次鼠标/键盘时生成非零 `trace`；同一次按住、松开、START、STOP 和服务端终态沿用它，`seq` 表示边界事件顺序。服务端再补充分配 `op`、可见 `workflow` 和持久化 `task`。搜索同一个十六进制 `trace`，即可跨客户端与服务端还原一次操作。

普通日志使用三个稳定前缀，并避免逐方块或逐 tick 刷屏：

- `[RTS-TRACE] side=C|S`：`INPUT_PRESS`、`INPUT_RELEASE`、`PACKET_SEND`、`NET_RECEIVE` 和客户端收到终态。
- `[RTS-DIAG]`：Pipeline `BEGIN/RESULT`、`WORKFLOW_CREATED`、`TASK_SUBMITTED/FIRST_SLICE/WAIT/RESUME/PROGRESS`、精确停止来源和 `TERMINAL`。
- `[RTS-SERVER-HEALTH]`：严重 tick 间隔及同期 RTS 切片、队列和持久化聚合；它只说明时间重叠，不把卡顿归因给某个模组。

`TERMINAL` 会说明任务是否真正执行过、从提交到首次 slice 等了多少 tick、完成/失败数量，以及是否与近期 tick gap 重叠。`PERSIST_LOAD_*`、`PERSIST_SAVE_*` 和 `PERSIST_STOP_RESULT` 用于判断旧任务从哪里恢复、保存是否 ACK；不记录绝对路径、完整 NBT、蓝图或库存。

独立结构化文件位于 `logs/rtsbuilding/diagnostics-client.jsonl` 和 `logs/rtsbuilding/diagnostics-server.jsonl`。写入队列有界且不阻塞帧线程或服务端 tick；文件约 8 MiB 后轮转到 `.2/.3`，停服/断线会尽力 flush。队列满或写盘失败只丢诊断并累计/告警，不改变玩法结果。

`diagnostics.level` 默认 `BASIC`，记录上述有界生命周期和百分比进度检查点；`VERBOSE` 额外允许每秒一次任务进度样本；`OFF` 关闭这些诊断。常见拒绝原因包括 `FEATURE_LOCKED`、`HARVEST_TIER_TOO_LOW`、`TOOL_CANNOT_HARVEST`、`OUTSIDE_SESSION_RANGE` 和 `CLAIM_DENIED`。排障时应同时提供客户端与服务端复现时段的日志；若需要 CPU 归因，仍需 Spark、JFR 等 profiler。

## 主要功能责任链

### 远程交互

客户端射线确定方块、方块面或实体，服务端重建有限的远程交互上下文，再调用目标或手中物品的正常交互逻辑。区块保护、会话维度和服务器范围仍需通过。按住 `Shift` 的自然交互与普通 RTS 交互是不同意图，排障时要记录实际按键方式。

### 单块放置与批量建造

服务端依次检查会话、维度、操作范围、插件/生存规则、区块权限和放置合法性，再从玩家背包或绑定储存取得真实 `ItemStack`。能力、NBT、耐久或能量变化必须保留在真实栈上。大型形状会拆成任务切片，由 Task Engine 分批放置；成功确认后客户端才播放放置动画并刷新材料/储存。

### 单块、连锁与范围挖掘

挖掘目标先经过软方块、插件采掘等级、真实工具可挖性、工具保护、范围、区块权限和特殊回收规则等检查。连锁请求受最大目标数和每 tick 处理数限制；范围请求另受各轴尺寸和总体积限制。

每次连锁/范围挖掘应拥有独立进度和任务身份；两个任务重叠时，后执行者必须容忍目标已经变为空气或被前一任务处理，不能重复产出。开启“回收 RTS 放置方块”时，已被记录为 RTS 放置的目标走专用回收规则，可绕过工具、采掘等级和精准采集门槛。

范围破坏提交时会冻结本次任务选择的工具槽位。已从绑定储存借出的真实工具优先使用；没有工具租约时，执行阶段读取任务冻结的快捷栏槽位，而不是可能已变化的会话旧槽位。采掘能力、工具保护和耐久写回都使用同一把真实工具。

### 撤回与重做历史

Ctrl+Z 使用服务端权威历史，并按原操作发生时冻结的创造/生存模式执行，不能通过撤回前切换模式改变资源或 NBT 规则。每名玩家只保留最近三次完整建造或破坏操作；单次记录超过方块数或压缩 NBT 上限时，整条历史会被拒绝并提示玩家，不保留不完整快照。

创造模式会保存建造前后或破坏前的完整 BlockState 与方块实体 NBT。Ctrl+Z 恢复操作前快照，Ctrl+Y 仅重做已经成功撤回的创造操作；新的世界修改会清空旧重做分支。生存建造撤回会移除本次放置成功的方块并将材料返还到绑定储存或玩家物品栏；生存破坏撤回只保存位置和 BlockState，不恢复方块实体 NBT，并从绑定储存、记录的工具栏槽位或明确回退来源支付所需方块。部分成功必须按具体位置裁剪历史，不能把未执行位置误判为已经完成。

挖掘产物先按正常掉落逻辑生成，再依据“自动入库”和已绑定储存尝试转移；无法完整入库时应保留明确回退路径，不能静默吞物品。

### 蓝图

蓝图客户端负责本地库、文件读取、捕获选择、命名、旋转、锚点、材料预览和虚影。提交放置时，服务端重新检查格式、非空气方块数量、缺失方块、插件、范围、材料、权限和放置合法性。大型蓝图进入持久化工作流和 Task Engine；任务元数据与较大的蓝图数据分开保存，以支持崩溃恢复而不把大对象反复塞进主存档。

机械动力等带方向、连接或方块实体数据的方块，需要经过蓝图变换和安全化链路；“外形扭曲”优先检查方块状态旋转、方块实体 NBT 变换和放置后的邻居更新。

### 储存、合成与漏斗

每个玩家/团队会话保存绑定端点、浏览页、过滤与会话开关。储存绑定只记录可验证的端点；浏览页由服务端快照构建并分页发送。AE2、Refined Storage 等大型网络的昂贵快照有刷新节流，客户端自动刷新并不等于每帧扫描网络。

提取必须保留来源返回的真实物品栈；工具、能量物品、背包和带能力/NBT 的物品不能只按物品 ID 复制后丢弃变化。操作后的剩余物优先退回原来源，失败时使用明确回退。

漏斗模式是持续动作：按住绑定键或右键时，客户端持续表达吸取意图，服务端按预算处理附近物品或流体。合成由服务端核对配方、材料、容器剩余物和目标储存。

### 插件、生存平衡与家园

关闭生存平衡时，插件和家园进度门不会限制正常 RTS 能力，但服务器的安全上限、区块权限和物品规则仍然有效。

开启后，服务端以玩家或团队的已安装插件快照为准。插件分别解锁控制、远控、储存、合成、连锁、范围破坏、蓝图、范围隐藏、外场部署、范围扩展和采掘等级。泥土、雪、沙子等软方块不要求采掘等级插件；石头及更高门槛方块同时要求对应插件等级和真实工具可挖。

没有外场部署时，玩家只能在家园区块及相邻八个区块组成的 3×3 区域内打开 RTS。成功打开后，本次操作范围以开启位置为中心，沿 X/Z 正负方向各延伸操作半径，形成正方形。家园负责“能否从这里开启”，会话锚点和半径负责“本次能操作哪里”。

### 范围隐藏与预览渲染

范围隐藏只改变客户端看到的方块，不修改服务端世界。每个存档/服务器身份应拥有独立记录，切换世界时不能复用上一存档的隐藏区域。

放置预览、破坏预览、选择框、骨架、方块虚影和确认后动画都属于客户端视觉层：

- **预览虚影/预览线框**：确认之前显示计划结果。
- **范围破坏骨架**：将非连锁范围的外边界合并显示；连锁挖掘固定使用骨架风格。
- **放置/破坏动画**：服务端确认世界变化后播放，不参与判定。

预览与执行必须共享形状、旋转、填充和目标坐标语义，但服务端仍会独立校验。渲染器不应结束或冲刷 Minecraft 的共享缓冲区；与 Sodium/Embeddium 等兼容问题优先检查渲染阶段、私有缓冲和状态恢复。

UI Core 状态快照可能在 `BuilderScreen` 构造期间生成。此时 Screen 尚未挂载到 Minecraft，构造期代码不能读取 `screen.getMinecraft()`；确实需要当前玩家状态时应使用可空的客户端单例，并在正式界面初始化后再读取依赖字体或尺寸的对象。

## 模组与服务器配置

在游戏内“模组 → RTSBuilding → 配置”保存的项目会立即写入配置并用于后续请求；手工编辑 TOML 时建议重启对应客户端、单人世界或专用服务器。

- **COMMON**：`config/rts_building/rtsbuilding-common.toml`。单人游戏读取本地文件；多人规则以服务器文件为准。
- **CLIENT**：`config/rts_building/rtsbuilding-client.toml`。只影响本机画面、确认方式和开发显示。
- **SERVER**：世界的 `serverconfig/rts_building/rtsbuilding-server.toml`（专用服务器位于当前世界目录）。只由服务端裁决。

## 现象到检查点

| 玩家看到的现象 | 可能停留的检查点 | 玩家可以先验证 |
|---|---|---|
| 按键或点击完全没反应 | UI 输入所有权、文本框焦点、当前模式、仍在等待 A/B 点、客户端未发包 | 关闭浮窗，按 `Esc` 取消当前工具后重选模式；说明按键方式和当前顶部栏模式。 |
| 长按破坏没有进度，或松开很久才停 | 同一 `trace` 的 `TASK_FIRST_SLICE`、`TASK_WAIT`、STOP 来源、服务端终态或 tick gap | 同时提供客户端和服务端日志；搜索同一十六进制 `trace`，对比首次切片等待、停止来源和 `TERMINAL`。 |
| 整个服务器同时卡顿 | `[RTS-SERVER-HEALTH]` tick gap、任务队列/运行数，或其他模组占用主线程 | 提供同一分钟的服务端日志；再用 Spark/JFR 采样，结构化日志只能说明时序，不能单独归因 CPU。 |
| 进度在重进后卡住、无高亮且叉号无效 | 持久化 Task 恢复、Workflow 投影超时、客户端未收到空闲状态 | 保留存档并提供退出前后日志；重新点击叉号会请求服务端权威状态对账。 |
| 预览正常，确认后没有执行 | 键盘最终确认、网络发送、会话/维度、插件、范围、权限或任务入队 | 按设置中的确认键；查看底部浮现提示和 `latest.log` 中是否出现请求/工作流。 |
| 需要点两次右键才交互 | 首次点击被拖拽判定、面板或模式切换消费；释放事件未形成交互 | 在无浮窗位置短按右键，记录第一次按下/释放后的模式与高亮是否变化。 |
| 连锁挖不了泥土、雪 | 不是采掘等级插件门，优先检查远程控制、连锁破坏插件、会话、权限或错误的软方块分类 | 改试单块挖掘；说明生存平衡、已装插件和目标方块 ID。 |
| 石头或矿石无法挖 | 采掘等级插件、服务端等级封顶、真实工具可挖性或工具保护 | 用原版钻石镐对比；确认石制/铁级/钻石级插件和浮现的需要/当前等级。 |
| 关掉生存平衡后恢复 | `ProgressionGate`、插件快照、家园开启限制或会话操作半径 | 刷新插件页；说明是否卸载后重装过插件、家园和打开 RTS 的位置。 |
| 超出家园附近不能开 RTS | 家园 3×3 开启门 | 回到家园区块或相邻八区块；检查是否安装外场部署。 |
| 能开 RTS，但远处不能操作 | 会话开启锚点的 X/Z 正方形半径、服务器最大半径 | 以打开 RTS 时的位置计算 X/Z ± 当前半径，而不是以家园或相机位置计算。 |
| 有材料但建造失败 | 物品身份/NBT、绑定储存快照、插件、区块权限、目标可放置性或任务队列已满 | 先用原版方块单块放置；刷新储存；检查目标是否可替换和 claim 权限。 |
| 蓝图某些朝向或传送带扭曲 | 方块状态旋转、方块实体 NBT、邻居更新或第三方兼容 | 用最小蓝图分别旋转 0/90/180/270 度；记录具体方块 ID 和蓝图文件。 |
| 挖下物品没有入库 | 自动入库关闭、未绑定、储存满、端点失效、掉落扫描半径或兼容提取/插入失败 | 手动刷新储存并尝试插入同物品；检查地面掉落和储存容量。 |
| 插件安装后仍未解锁 | 服务端插件快照未刷新、团队归属变化、安装事务未持久化 | 打开插件页点刷新；退出重进后确认已安装列表和贡献者。 |
| 范围隐藏跨存档出现 | 隐藏区域持久化键没有区分存档/服务器身份，或切换世界未清理 | 记录两个世界名称/服务器地址和维度；清空范围后复测切换。 |
| 只有预览或动画消失 | 对应客户端开关、渲染阶段、共享缓冲冲突或优化模组兼容 | 同时检查虚影与线框开关；暂时关闭 shader/优化模组作对照。 |
| 大任务卡顿或进度慢 | 每 tick 单项上限、全局 Task Engine 单位/时间预算、其他玩家任务竞争 | 缩小目标作对照；记录服务器 TPS、目标数和同时运行的工作流。 |
| 储存页面更新慢 | 自动刷新周期、免打扰仅隐藏提示、AE2/RS 快照节流或网络规模 | 点击手动刷新；说明储存类型和网络规模。 |

## 提交排障信息

最有价值的信息是：RTSBuilding 版本、Minecraft/加载器版本、单人或服务器、当前模式、生存平衡状态、已安装插件、目标方块/物品 ID、使用的真实工具、绑定储存类型、从进入 RTS 开始的最短复现步骤，以及复现时的 `latest.log`。

信息不足时，应先给安全且可逆的检查路径，再追问最关键的 1–3 项；不要一开始要求玩家上传全部模组列表。教程和附录无法确认原因时，应明确说明未知，不要把推测说成结论。
